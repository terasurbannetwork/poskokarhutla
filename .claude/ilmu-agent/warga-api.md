## Peta berkas & tabel

**Berkas (semua di `src/`, ESM tanpa bundler, Cloudflare Worker + D1 + R2):**

`worker.js` (fetch, scheduled, tabel `RUTE`, `cacheTepi`, `/api/status`, `bersihkan`), `foto.js` (`RUTE_FOTO`, R2 `MEDIA`), `titik.js` (cron FIRMS, `wilayah`), `statistik.js`, `publik.js`, `admin_halaman.js`, `og_meta.js`; modul lain: `ls src/`.

Konfigurasi: `wrangler.jsonc` (PRODUKSI: D1 `DB`, ASSETS `html_handling: "none"`, satu cron `17 * * * *`, TANPA r2_buckets),
`wrangler.warga.jsonc` (USULAN lengkap: + `r2_buckets MEDIA` bucket `poskokarhutla-foto`, cron kedua `15 */3 * * *`).
Dokumen: `WARGA.md` (§Deploy 76, §Moderasi 110, §Statistik 153, §Foto 174). Klien: `public/warga/index.html`,
`public/informasi.js`, `public/foto.js`, `public/admin/{statistik,pesan,foto}.js`.

**Rute:** tabel `RUTE` di `src/worker.js` + `RUTE_*` tiap modul (kunci `METODE /jalur`, `:id` = 16 hex di ujung). Daftar lengkap = `tests/warga/cakupan.json`; kode menang atas ilmu. Auth: publik, laju per hash IP, `adminOK`.

Tabel D1: baca `migrations/` (0001 laporan/kontak/suara, 0002 titik_terbaru, 0003 audit_moderasi, 0004 statistik+laju, 0005 pesan, 0007 foto); CHECK katalog `jenis:sub` harus sama dengan `public/informasi_jenis.js`.


**Cron:** `15 */3 * * *` (`CRON_TITIK`) menarik FIRMS; `17 * * * *` bersih-bersih (kontak 72 jam, laporan kedaluwarsa, jejak, retensi). R2 foto `foto/<id>` dan `_t`, tanpa `MEDIA` = 503. Free: CPU 10 ms, tulis D1 100 rb/hari: jangan tulis per kunjungan.

**Secret/var (hanya nama):** `IP_SALT` (wajib untuk POST), `ADMIN_TOKEN` (boleh banyak, koma), `SESI_KUNCI`, `TURNSTILE_SECRET` + var `TURNSTILE_SITEKEY`, `FIRMS_MAP_KEY`, `EMAIL_API_KEY`, `EMAIL_TO`, `EMAIL_FROM` (Resend). Lokal: `.dev.vars` (di-gitignore; contoh `.dev.vars.example`).


**Uji:** Miniflare dengan `modules`, D1 `DB`, ASSETS dari `public/`, fixture keluar; migrasi lewat `migrasi()`+`pecah()` di `tests/warga/_bantu.mjs`.

## Aturan & invarian

- IP mentah tidak pernah disimpan: `ipHash` = SHA-256(`IP_SALT|kunciIP`); IPv6 dikunci ke prefiks /64 (`kunciIP` 105). Kolom `ip_hash` tidak pernah keluar di respons publik (`KOLOM` 131, `KOLOM_PUBLIK` foto.js:55).
- Kontak WA hanya lewat `POST /:id/kontak`, tidak pernah di daftar/rincian; dihapus saat selesai/disembunyikan/72 jam.
- Respons sukses lewat `json()` (`cache-control: no-store`, nosniff); hanya GET publik tanpa data per pengguna yang boleh lewat `cacheTepi`. Admin/POST/bercookie TIDAK PERNAH.
- Urutan gerbang di rute tulis: CSRF origin (di `rute()` 388) -> `IP_SALT` ada (503) -> `bacaBody` (maks 4096 B) -> validasi -> Turnstile -> `cekLaju` -> tulis. Aksi admin: `adminOK` PERTAMA, sebelum body/D1.
- Aksi admin selalu dalam satu `DB.batch` bersama baris audit (`audit_moderasi` / `audit_foto`); hapus laporan = soft delete.
- `hapus_pengirim` wajib `konfirmasi` = jumlah laporan terdampak (CGNAT: satu hash IP bisa banyak warga).
- Teks publik lewat `bersihTeks` (buang URL & nomor HP, tolak kata kasar, maks 280); detail lewat `bersihDetail`; lokasi satwa dibulatkan 0,01 derajat.
- Foto: lokasi = GPS perangkat (akurasi <= 1000 m, umur <= 10 mnt), EXIF GPS <= 5 km dan waktu <= 48 jam; tipe dari byte awal (`jenisBerkas`), bukan Content-Type; foto 3 MB, video 30 MB / 60 dtk, thumb 300 KB; berkas R2 dibuang bila INSERT gagal.
- Foto baru `menunggu`; hanya `tayang` yang terlihat publik; 3 aduan IP berbeda mengembalikan foto ke antrean.
- Migrasi: berkas bernomor, baru = berkas baru, yang sudah jalan tidak disunting (lihat ilmu `migrasi-idempoten`). Daftar `jenis:sub` di `0001` dan `public/informasi_jenis.js` harus sinkron.
- Rute/tabel/trigger baru WAJIB masuk `tests/warga/cakupan.json` (diuji dengan nama uji nyata, atau dikecualikan dengan alasan >= 15 karakter).

## Ranjau yang pernah meledak

- **Deploy produksi vs `wrangler.warga.jsonc`:** cek `grep -c r2_buckets wrangler.jsonc` dan cron di kedua berkas sebelum menjanjikan foto atau FIRMS D1 (kode menang atas catatan ini).
- **Roster:** `17 * * * *` = bersih-bersih, FIRMS = `15 */3 * * *`. **Migrasi kembar `... 2.sql`** (salinan Finder) menggagalkan `d1 migrations apply`; `.gitignore` menolaknya.
- **Cabang lama `/api/warga` di `fetch`** (454-457) memeriksa origin tanpa pengecualian `"null"`: `new URL("null")` melempar -> 500 "galat server". `rute()` (388) sudah benar. Rute baru taruh di tabel `RUTE`, jangan di cabang lama.
- **CHECK SQLite tidak bisa di-ALTER:** `jejak.aksi` beku, jadi laju baru memakai tabel `laju` (0004) dan `foto_laju` (0007). Memperlebar CHECK = bangun ulang tabel (contoh `0006`).
- **CHECK dengan NULL lolos diam-diam:** `durasi` video di 0007 memakai `coalesce(durasi, 0)`; `0004` memakai `coalesce(json_type(...), '')`.
- **`wilayah()` di-cache di variabel modul** (`WIL`); uji yang mengganti aset harus memakai isolat baru.

### Router & rute
- `rute()` hanya GET/POST dan `:id` 16 heks di AKHIR jalur; kunci hanya `[\w/:]` (berstrip `-` tak terbaca regex gerbang/cakupan: pakai underscore). Jalur bersarang: aksi sebelum id (`/api/alun/<aksi>/:id`, `/undang/cabut/:id`), POST `/:id` untuk koreksi (PATCH tutup titik TP- = POST `/api/pengungsian/titik/tutup {id}`), atau alternatif regex di `rute()` (`/renlap/:id/pdf`, `/api/sippa/data/:nama`, `lb` entri|tutup|sk, `lp` untuk `/api/lapor/meja/:x` dan `/s/:x`, token lacak 36 heks lewat `halamanLacak` + `x-lacak`). Rute bersarang tanpa regex = 404 padahal ada di RUTE_*. PATCH/DELETE id bilangan butuh regex; `tolakOrigin` juga untuk PATCH/DELETE. POST ke rute GET-only = 405; HEAD butuh kunci RUTE sendiri (tanpa itu anonim 200).
- Cookie `sesi_instansi` hanya Path `/instansi` dan `/api/instansi`: rute klien `/instansi` (termasuk LogPal `/instansi/logpal`, `/api/instansi/logpal/*`) WAJIB di bawah `/api/instansi`.
- `/ubin/` paling awal di `fetch()`; `head()` lalu `get({range})`; Cache API menolak `put()` 206 (simpan 200 bertanda `x-ubin-status`). `assets.run_worker_first` larik ditolak wrangler@3 (`terbit.yml` pakai @3).
- `adminOK` PERTAMA sebelum validasi param (tamu tak membedakan 400/404); R2 tanpa bucket = 503; khusus-login = `adminOK` ATAU `pemirsaSesi`. Secret akun gerbang satu definisi (`akunGerbang`) untuk `adminOK` DAN `modOK`. Gerbang situs DEFAULT TERTUTUP (`PUBLIK_TANPA_SESI`); staf lewat `modAtauStaf`/`stafNyata` (dummy=0, akun gerbang 403). Sub-router yang harus lolos gerbang situs dipasang di `layani()` SEBELUM gerbang. Gerbang modul pakai daftar peran eksplisit (P_AKADEMISI), bukan `Object.keys(PERAN)` (operator_cc lolos 15 titik; `akademisi_peran.test.mjs`).
- Body per byte (`bacaBytes`), kelebihan dibuang s.d. 8x batas (keep-alive). Batas umum `bacaBody` 4096 (413): isian panjang diberi batas per rute. Login: sandi DULU, kunci per username+IP, CSV `wajib_ganti`, terkunci tak menulis `laju`.
- Gerbang WA: tulis `x-wa-kunci`, baca `adminOK`/Bearer `WA_MESIN`; idempotensi dicek SEBELUM put R2; tanggal `wa_masuk` = tanggal isi bila dalam [terima-14h, +1h]; daftar R2 per tanggal lewat customMetadata + `list(include)` sekali.
- Aduan 3 suara = sembunyi otomatis wajib Turnstile; jenis bantuan dikecualikan (`suara_tambah` 0069, `salah>=3`).
- Impor: uji impor `src/worker.js` SEBELUM modul rute (`RUTE_*` dispread saat evaluasi; TDZ RUTE_LAPOR). Siklus impor aman bila rute diekspor sebagai fungsi (ruteAkun) atau hanya dipanggil saat permintaan; `src/siklus.js` dipasang SESUDAH import berantai.js. `public/*.js` yang diimpor worker: tanpa `import("node:...")` (pakai `process.getBuiltinModule`). Impor `src/`->`public/` baru dan berkas data bundel WAJIB masuk `copyFileSync` di `api.test.mjs` (gejala ENOENT berantai). Data bundel = modul ESM `export default`, BUKAN .json (Miniflare ERR_MODULE_PARSE). `jaga()` harus meneruskan ctx dan x (dulu rute `:x` selalu 404).
- Spread RUTE yang menimpa diam-diam: cek kunci lama dulu (`grep -n "/api/lapangan" src/posko.js`; 15 uji posko pecah).
- Iframe sesama asal butuh CSP frame-ancestors 'self' + X-Frame-Options SAMEORIGIN + rute halaman terdaftar.

### Migrasi & skema D1
- ALTER ADD COLUMN tidak idempoten: tabel samping (`tugas_kartu` 0041, `tugas_bencana` 0047, `lkb_*` 0048, `lapor_kejadian` 0160) atau JSON. CHECK tak bisa diubah (`pemirsa.tab` <=7, `laju_posko.aksi`; laju baru lewat `laju_bnpb`).
- Bangun ulang tabel: salin ke cadangan (`CREATE TABLE AS`/korban_cadang), DROP, CREATE, isi, trigger IF NOT EXISTS; JANGAN `ALTER ... RENAME` (memeriksa SELURUH skema, menggagalkan uji 'tanpa 0029' lewat trigger gudang_prov_sah). Uji 'tanpa migrasi X' ikut membuang migrasi yang bergantung (0043 butuh 0029; anak ber-FK 0041/0042).
- Yang memaksa bangun ulang CHECK: bencana baru di registry (laporan.bahaya pola 0020 + laporan_wilayah dicadangkan, stat_hari.hal pola 0017, seed foto_kategori di `00NN_<id>_rujukan.sql`); hazard korban (0093); jenis pengingat (pola 0088, `pengingat.test` banding DAFTAR_JENIS); meja baru (meja_petugas json_array_length + meja_ringkas, 0118); peran staf baru = LIMA ubahan (trigger staf_larik_sah/ubah pola 0085, PERAN src/staf.js, SEMUA_PERAN admin_halaman.js kecuali peran tanpa /admin/kinerja, PERAN public/admin/pantau.js, uji membaca trigger dari migrasi TERAKHIR).
- `pecah()` memotong di baris berakhir `;`: komentar `--` di baris sendiri. CHECK tanpa subquery (trigger). `cakupan.json` memindai SEMUA `CREATE TABLE`; 'diuji' = AWALAN nama uji literal `uji("...")`. Nomor migrasi: `ls migrations` tepat sebelum menulis. Hash baru wajib di `migrasi_beku.json` (`tests/warga/migrasi_beku.test.mjs`).
- FK: `gudang.akun_id ON DELETE CASCADE`; `alat_jejak` tanpa FK; sumber polimorfik (`foto_label` 0071) tanpa FK. FK ke sk_kejadian butuh indeks anak (sk_gl_kej) agar DELETE tak SCAN.
- Kode bisa terdeploy sebelum migrasi: statement tabel baru SESUDAH batch dengan try/catch 'no such table'; fallback CREATE TABLE di jalur tulis PERTAMA (`sungai_tanpa_migrasi.test.mjs`); cek tabel sekali per isolate (true dicache, false dicek ulang 5 mnt; `logbook_tanpa0094.test.mjs`).
- Alur status dijaga trigger BEFORE UPDATE, diuji semua pasangan terhadap spek JS; jejak `INSERT..SELECT..WHERE changes()>0` dalam batch. Balapan deterministik lewat TRIGGER AFTER INSERT di `laju_bnpb` (409). Append-only: BEFORE UPDATE/DELETE tak menahan INSERT OR REPLACE, tambah BEFORE INSERT WHEN EXISTS. Trigger beku butuh pengecualian sempit untuk penanda sah sesudah beku (ku_rekomendasi.tidak_dilanjutkan 0->1).
- `changes()`: INSERT OR IGNORE 0 baris memutus rantai `WHERE changes()>0` sesudahnya (penanda di AKHIR batch); `meta.changes` D1 ikut menghitung baris pemicu (cek > 0, bukan === 1); bila rantai rapuh pakai EXISTS (pindah ketua, cabut nihil). INSERT OR IGNORE melewati pelanggar CHECK diam-diam (uji CHECK pakai INSERT biasa). INSERT..SELECT beragregat tetap menyisip tanpa HAVING.
- Kunci idempoten luring: (oleh, klien_id) meja_catatan, (catatan_id, klien_id) meja_jejak, `relawan_jam.klien_masuk/keluar`; `meja_stok` belum (tambah UNIQUE (gudang_id, klien_id) dulu). `waktu_klien` hanya bila <=5 mnt depan, <=14 hari. UNIQUE dengan kolom NULLable tak menegakkan apa pun (UNIQUE INDEX + coalesce).
- CHECK `kedaluwarsa <= dibuat+7 hari`: uji yang menggeser `dibuat` geser juga kedaluwarsa. `meja_id` length=16. `prioritas_dampak` keadaan = kelas, bukan tanggal. `hex()` huruf besar: pakai `lower(hex(randomblob(8)))`.
- D1 menolak ORDER BY subquery berkorelasi ke kolom luar CTE (node:sqlite lolos): pakai `= (SELECT min(abs(..)))`. FTS5 unicode61 tanpa stemming. Indeks parsial hanya terpakai bila WHERE memuat predikat persis; planner tanpa statistik memilih SCAN: paksa CROSS JOIN + INDEXED BY, cek EXPLAIN QUERY PLAN di uji (indeks ekspresi meja_catatan hanya melayani meja+prov, kab disaring di JS).
- Saring lingkup/awalan di SQL SEBELUM LIMIT, bukan di JS (menggusur baris sah); batas baris lewat predikat count(*); batas anggota atomik lewat INSERT..SELECT WHERE count<maks.
- Data besar: CHECK 1 MB `logpal_statis` + batas 100 KB per pernyataan -> potongan 90 KB (0113).
